## 0. 起因

用户："敞口太大了、单个标的仓位过重了、有大跌信号了、仓位需要调整了、熔断
了……为什么不能考核？" —— 门⑤ v1 只考核了止盈/止损/到期/对冲，而这些
breach 检测逻辑代码里早就有（`scoring/position_exposure.py::breaches()`、账户

信号一样：现算现显示，没有"哪天冒出来的、你几天才调回线内"的记录。

- **门④"复核"** = 往前看，下单前该检查的（Firstrade 没 API，抓不到下单
  那一刻，所以做不了硬拦截，只能事后从 `transactions` 检测）
- **门⑤"纪律"** = 往回看，系统说了"必须调整"、你有没有真的回去调

**熔断语义纠正**：这个系统的"熔断"是**每只股票的评分机制**（`CIRCUIT_MULTIPLIER`
压低那只票的 `final_score`，`decision_policy.py` 标"🧾 熔断复核 · 需人工复核"），
**不是账户层面停止交易**。所以熔断的纪律含义是"你有没有在一只评分被熔断
压制的票上开仓"，归到"无视系统红旗"这一类（跟 #14 无 case 交易是近亲），
中权重，普通事件打分，没有"熔断期间加仓 −1.0"那种特殊重罚。

- **止盈信号（单独）**——提前止盈是选择不是义务，不做不算失纪律。只做展示 +

- 逼近限额（approaching，还没突破）
- 压力测试轻度警示（−8% ~ −12%）
- 单独的 MAJOR 回调（没有浮盈可保护、没踩硬约束、论点也没转 SEVERE）——
  单纯技术回调要不要离场取决于论点，系统不越过论点判你"必须动"

### 这轮不做（记下）

- **论点纪律**（SEVERE/WATCH 转变触发）——"响应"定义太模糊（SEVERE 下减仓

- **逆势加仓 / 亏损加仓**——价值高，但"逆势"判定要依赖论点状态，一起留二期
- **限额放宽滥用 / limit creep**——哈希链已经有了，但慢变量、短期数据少看不出
  趋势
- **门④"下单前参考页"**——Firstrade 没 API，做不了硬拦截；一个纯参考页（显示
  当前硬约束余量 / Kelly 建议张数 / 有没有 case / 是不是熔断票）v1 不做，
  **也不追踪"你有没有点开它"**——为平台限制去考核用户的自觉是本末倒置。
  等实际交易几周、清楚了它该放什么再补。
- **EWMA 近期加权**——v1 窗口内平权，以后再加（跟门③绩效 λ=0.94 一致）
- 过度交易 / 换手率、决策反复（48h 反手）、止损后 revenge 重进、简报 🔴 建议
  未执行——都需要先标定基线，二期

## 2. 打分模型

### 2.1 纪律分 = 百分制合规率，90% 才及格

```
纪律分 = Σ(事件分 × 维度权重) / Σ(维度权重) × 100%
```

- **没有负分**——最坏是 0 拖累百分比；严重程度全靠三档权重表达（一个高
  权重事件失守，对百分比的拉低是低权重的 3 倍）
- 分档：**≥95% 优秀 · 90–95% 及格 · 80–90% 警示 · <80% 严重失守**
- 默认周期**滚动近 30 天**（对"最近是不是在松懈"敏感），可切 90 / 365
- 总分下面永远摊开每个维度的响应率——总分绝不能掩盖是哪个维度在垮
  （门③做 Kelly 分桶时的教训）

### 2.2 事件分（每个信号在"了结"那刻定死）

| 了结方式 | 事件分 |
|---|---|
| 窗口内你真的调了仓 | **1.0**（门④违规类上限 **0.75**——是你造成的，最好情况也留个小痕） |
| 超窗口后你调了（迟响应） | **max(0, 上限 − 0.15 × 迟了几天)**，迟满 7 天 = 0，之后再补也是 0 |
| 自动漂回线内（你没动，市场自己回去的） | **0，扁平扣满**——不响应就是不响应，运气不洗白 |
| 从没解决 / 到期被动了结（expired_unhandled） | **0**（放高权重档，靠权重让它疼） |

- **"迟了几天" = 解决那天 − 信号首次出现 − 响应窗口**，且**只算到信号了结那天
  为止**——不管是你调回去的还是漂回去的，一旦不再是 breach，计时就停，
  这个事件从"N 条超期"列表消失、分数定死
- 信号还挂着没了结时：在当期分里算一个**临时的 0、一直拖累**，直到了结

**例**：止损信号（上限 1.0，窗口 2 天），你第 5 天才平 → 迟 3 天 →
`max(0, 1.0 − 0.15×3) = 0.55`。第 10 天才平 → 迟 8 天 → **0**。

### 2.3 三档权重

见 §1 的表。原则：**按"忽视它的最大伤害"分档**——
- **高 (3)**：忽视 = 灾难性 / 不可逆损失（强制去风险、止损、止盈+回调、
  BD/杠杆超硬上限、压力测试超红线）
- **中 (2)**：忽视 = 风险画像恶化，但不至于当场爆（单票/集中度超限、对冲违规、
  开仓恶化 breach、到期未处理、熔断票交易）
- **低 (1)**：忽视 = 次优但可恢复（现金底线、流动性天数、偏离 Kelly、无 case 交易）

## 3. acted vs self_resolved 判定（沿用 v1 核心，按信号类型细化）

一个信号不再触发了，**只有能找到对应的真实动作**才算 `acted`；否则
`self_resolved`（市场自己漂回来的），扁平 0。数据靠 `transactions`（1311 条
完整买卖流水，股票+期权都有）——持仓快照历史基本没有（`positions` 现在只有
1 个时点、`options_positions` 连 sync_time 列都没有），只能靠"有没有一笔对应
交易"来推断。

| 信号类型 | acted 判定 |
|---|---|
| 能归到具体标的（止损、单票超限、集中度超限、流动性/退出天数、门④ #12） | `transactions` 里在 breach 首次出现之后、消除之前，那个标的有一笔**减仓方向**交易（多头卖出 / 空头回补） |
| 组合层面（BD 比率、Delta 杠杆、压力测试超红线、强制去风险） | 窗口内有**任何一笔降风险动作**（卖出，或新开保护性对冲）——归因更糊，但"你到底有没有做任何降风险的事"这个问题本身是诚实的 |
| 到期处理 | 到期前平仓了（`option_realized_trades.close_date < expiry`）→ acted；DTE 到 0 还挂着 → `expired_unhandled` |
| 对冲纪律 | 加了对冲 / 触发条件清除且有对应对冲交易（沿用 v1） |

**注意**：仓位管理页面已有"超限期间无法调高该限额，只能调整持仓"这条硬规则
——意味着 breach **不可能靠"放宽限额"消除**，少了一类最恶心的假
self_resolved。

**v1 已知局限延续**：门⑤ v1 用 `option_realized_trades` 检测 acted，会漏"你
用交易正股来响应期权信号"的情况——v2 改成查 `transactions`（含正股）能补上
一部分。

## 4. 门④违规的特殊处理（下单即违规，没有"响应窗口")

#12 开新仓恶化 breach、#13 偏离 Kelly、#14 无 case 交易、#11 熔断票交易——
下单那一刻要么违规要么没有，事后没有"响应窗口"可言。用**可补救 + 时间衰减**：
先扣分（事件从 0 起），短窗口内做纠正动作 → 按 §2.2 的衰减公式往上限
（0.75）方向升，越拖折扣越少。

| 维度 | 纠正动作 | 补救窗口 |
|---|---|---|
| #12 开新仓恶化 breach | 把那笔敞口减回去（该标的一笔减仓交易） | 3 个交易日 |
| #13 偏离 Kelly（超配 / 负收缩 Kelly 还交易） | 削回建议区间内 | 3 个交易日 |
| #14 无 case 交易 | 在"误价研究"页补出该标的的 case | 5 个交易日 |
| #11 熔断票交易 | 写一条复核理由（跟改限额要写理由一个道理） | 5 个交易日 |

#12 造成的 breach 照常走 #4/#5/#8 等自己的信号——两条记录量的是两件事：
"你把它搞更糟了"（动作，#12）vs"它现在还是糟的"（状态，#4/#5），不是重复罚。

## 6. 复核仪式（"纪律与复核"的复核那一半）

- **每周**，一个**页面**（不是弹窗）
- 摆出这段时间"未响应 / 迟响应 / 自然消失"的信号，逐条让你标注：
  | 标注 | 打分影响 |
  |---|---|
  | **有意例外**（+ 书面理由，≥ N 字） | **整条从分数里剔除**（分子分母都不算）——你做了有记录的主动判断，等于一次书面豁免 |
  | **漏了** | 按未响应 / 衰减扣，不打折 |
  | **不认同信号** | 剔除，同时标记去调那个维度的阈值 |
- 不做复核**不冻结分数**，但页面顶部显示"N 条待复核"

## 7. 回调模块（MAJOR 回调信号）

之前 `SIX_GATES_AND_EXPOSURE_DESIGN.md` §3.5 只记了问题、没设计。现在上关键
路径（#15 复合信号靠它触发）。

### 是什么 / 不是什么

- **是**：对**已持仓**标的，判断"短期价格结构坏没坏到该保护浮盈 / 该复核是否
  离场"。逐个持仓标的跑，每次同步跑一遍。
- **不是**：入场信号、大盘择时、"还会继续跌"的预测。现有 `score_momentum()`
  用 200 日均线（约 10 个月）+ RSI-14，周期完全不对，不复用。

### 5 个检查（波动率归一，不看绝对百分比）

| 检查 | v1 阈值 |
|---|---|
| 距近期高点回撤 | 现价比过去 **20 个交易日最高价**低 ≥ **2 × ATR14** |
| 跌破短期结构位 | 现价收在 **20 日均线之下**（之前在上方） |
| 短期动能翻负 | **10 日 ROC** 由正转负 |
| 下跌速度 | **3 个交易日内跌 ≥ 1.5 × ATR14** |
| （可选）放量 | 跌的那几天成交量高于 20 日均量——v1 先不要 |

### 两档

- **观察（WATCH）**：满足 1 项 → B 类，页面显示，不进纪律分
- **重大回调（MAJOR）**：满足 ≥ 3 项，**或**"下跌速度"单独触发 → 有资格进 #15
  复合信号

### 数据 / 参数

- `yfinance` 拉每个持仓标的近 3–6 个月日线（war_room.py / pages/5 已在用
  `yf.Ticker(t).history()` 这个模式），pandas 现算 20 日高 / 20DMA / 50DMA /
  ATR14 / 10 日 ROC / 3 日收益。AlphaVantage MCP 有 ATR/ROC/SMA 端点可做第二
  源，v1 用 yfinance 一个源够了。
- 待调参数：`2×ATR`、`1.5×ATR/3日`、`20 日回看`、`≥3 项算 MAJOR`——v1 默认。
