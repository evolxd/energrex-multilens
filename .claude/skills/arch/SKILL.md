# 技能：System Architecture & Structure Specification (arch)

## 一、 核心职责
定义系统的空间结构、边界隔离、协作契约与拓扑图谱规范。
本规范指导跨模块设计、新模块落盘、核心引擎剥离，以及系统架构资产的可视化沉淀。

---

## 二、 三层空间拓扑结构与隔离红线

系统严格遵循自外向内的单向依赖：
外层 (UI/CLI/调度器) -> 中间层 (Services 适配编排) -> 内核层 (Domain 纯计算引擎)
底层基础设施 (DB/缓存) 仅通过依赖注入向内核提供数据。

### 1. 核心领域层 (Domain Engine)

* 职责：承载核心计算、估值算法、状态识别与业务实体。
* 强制红线：
   * 禁引外围框架：绝对禁止引入任何 UI 框架（如 streamlit 等）以及底层网络/数据库直接驱动。
   * 无副作用纯内存：必须为纯函数或无状态计算类，接收纯净数据对象，产出计算结果，禁止内部触发隐式 IO。
   * 生命周期独立：不依赖任何外围框架的初始化或文件行号截止规则，可独立脱机运行与测试。

### 2. 中间适配与编排层 (Adapters / Services)

* 职责：组装用例、数据流调度、参数清洗与模型转换。
* 约束：作为外围与内核的桥梁，负责将底层取出的原始数据格式化为领域层所需数据结构并调用内核。

### 3. 外围驱动与基础设施层 (UI / Infrastructure)

* 职责：页面展示、CLI 交互、定时任务调度、物理数据库读写。
* 数据注入原则：计算所需数据必须由本层加载后，以参数形式向下传递给内核，严禁内核向上索取。

---

## 三、 模块间协作契约规范

### 1. 废除暗箱与动态反射

* 严禁使用字典键名反射（如 globals()['func_name'] 或动态 dict-key 取用未声明函数）跨模块调用。
* 严禁依赖隐式运行时加载切片规则。

### 2. 显式契约 (Protocol-First)

* 跨层或跨模块调用，必须使用 typing.Protocol、抽象基类（ABC）或标准 Type Hints 声明接口契约。
* 契约必须显式定义输入字段、输出类型及异常类型，确保静态类型检查可完全覆盖。

---

## 四、 架构可视化与图谱沉淀规范

每次进行跨模块抽取或核心引擎重构，必须同步产出结构图谱，并严格遵循双层存放机制：

### 1. 细节数据流与算法拓扑图

* 存放路径：项目根目录下的 docs/architecture/<MODULE_NAME>.md 或对应的专属架构文档中。
* 格式要求：统一使用 Mermaid 语法，清晰标识函数调用流向、分支判断点及状态变迁。

### 2. 全局架构索引维护

* 系统架构主文档中仅维护系统全局鸟瞰拓扑图及各子模块的图谱路径索引，禁止将数百行的细节流图全量堆入顶层规范中造成上下文膨胀。

---

## 五、 架构重构验收清单 (Architecture Checklist)

* [ ] 核心计算模块是否完全脱离 UI 与持久化 IO 依赖？
* [ ] 模块测试是否能在内存中直接运行（无需打桩全局数据库）？
* [ ] 跨模块调用是否存在静态扫描盲区或动态反射？
* [ ] 本次架构调整是否已产出对应的 Mermaid 依赖/流向图并落盘文档？
